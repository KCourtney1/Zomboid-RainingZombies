# Playtest: October 25, 2026

## Author-reported results

Tested in Louisville with zombie density set to high:

- The previously observed stuttering was gone.
- Stair fights caused no knockdowns while moving up or down.
- Zombies still jumped from ledges and windows.
- Falling zombies damaged and knocked down the player and knocked down other zombies.

These are user observations, not instrumented performance measurements. The exact
mod list, test duration, coordinates, sandbox values, and frame times were not recorded.
The earlier smoke test also confirmed successful loading without observed errors.

## Unresolved observation: possible wall crossings

Some zombies appeared to pass through walls before falling toward the player.
The author could not distinguish this reliably from zombies falling from a roof.
There is not yet a controlled in-game reproduction.

Inspection of the current `RainingZombies_Logic.lua` confirms three relevant gaps:

1. A missing destination floor (or missing square) permits a vault without a wall check.
2. The window/fence lookup searches whole tiles without matching the crossed edge.
3. The lookahead is one direction-vector unit, while the actual position push is
   0.6 units. They can select different destination tiles near corners.

Two ad-hoc scenarios used the existing Lua 5.1 engine doubles, without changing
production code or the test suite:

| Setup | Result |
| --- | --- |
| Start at X=10.8, facing east, origin reports a blocked boundary, floorless square ahead | X becomes 11.4; fall starts; boundary query never called |
| Same eastward approach, north-facing open window on current tile, blocked east boundary and floored destination | X becomes 11.4; fall starts; boundary query never called |

The doubles demonstrate the unchecked decision path. They do not model collision
resolution, prove what the author observed, or establish a fix. Gameplay code was
left unchanged during this investigation so the working playtest baseline is retained.

## Next fix and controlled retest

The next geometry change should validate the actual crossed boundary before
moving a zombie. Windows/fences must belong to that boundary; solid walls,
barricades, closed doors, and diagonal corner crossings need explicit handling.
Missing destination squares need careful treatment so legitimate ledge falls
are preserved. Confirm the behavior of the installed Build 42 boundary APIs
before implementation; public signatures alone do not establish semantics.

A custom map is optional. An existing cleared upstairs room with one spawned
zombie can provide controlled comparisons:

1. Solid exterior wall with a drop outside: no forced crossing.
2. Same setup facing an open window: a fall remains possible.
3. Closed window, then barricaded window, with shatter disabled: no forced crossing.
4. Open window on the adjacent wall while the zombie faces a solid wall: no crossing.
5. Roof edge with no barrier: a fall remains possible.
6. Repeat from the opposite side and near a corner.

Keep the player, zombie count, floor, and relevant sandbox settings controlled.
Record video and the floor/position if the apparent teleport recurs. Recheck
stair fights and high-density performance after the geometry fix.


## Follow-up: attacking zombie disappears beside an opening

The author clarified that both the player and zombie were on the same upper
floor beside an opening. The zombie performed its grab/bite animation, then
disappeared after a few bites and later returned upstairs. A forced shove followed
by a survived fall is a plausible explanation; the actual fall was not observed.

The tested implementation did not exclude attacking zombies. In a synthetic
650-tick attack, it moved the zombie from X=10.2 to X=12.0 through repeated
0.6-tile pushes after tracking expired. An attacking zombie could also trigger
Instant Glass Shatter. These regression cases failed before the fix.

A narrow guard now skips new vault decisions when `zombie:isAttacking()` is true.
The installed Build 42.21 implementation delegates that method to the current
state's attack predicate, and AttackState returns true. Normal vaulting resumes
after that predicate becomes false; the fall tracker continues handling zombies
that were already falling. The attack guard adds no per-zombie storage.

All 23 Lua 5.1 test methods pass, including the attack regression cases. The
author subsequently confirmed that attackers no longer disappear. With the
player on the same floor and their back to the window, one zombie did not jump;
crowds could still produce falls near the opening. The cause of those crowd
falls was not isolated. This does not fix the separate boundary/orientation
gaps above, nor prevent vanilla physics or other mods from moving a zombie.

Singleplayer debugging is paused at the author's request. The next development
target is hosted co-op, separate from this release.
